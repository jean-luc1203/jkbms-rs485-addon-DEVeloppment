# Standalone Docker image for JK-BMS-RS485 & CAN bus

This image allows you to run the **JK-BMS-RS485 & CAN bus** as a standalone container alongside a **Home Assistant Container/Docker** installation (without the Supervisor).

The image embeds the Node-RED implementation of the add-on and exposes its configuration through Docker environment variables.

## Build the Docker image

### Local build

From the root of the repository:

```bash
docker build -t jkbms-rs485-standalone -f standalone/Dockerfile .
```

### Multiplatform build with a Docker registry

Prepare a multi-platform Docker builder once:

```bash
docker buildx create --use --name multiarch-builder
```

Login to the registry:

```bash
docker login {registry}
```

Build and push:

```bash
docker buildx build \
  --platform linux/amd64,linux/arm64/v8 \
  -t {registry}/{owner}/jkbms-rs485-standalone:latest \
  -f standalone/Dockerfile \
  --push \
  .
```

## Home Assistant dashboard synchronization

Standalone Docker does not have the Home Assistant Supervisor WebSocket endpoint.

The container therefore connects directly to the Home Assistant WebSocket API.

Create a **Long-Lived Access Token** in the Home Assistant user profile and provide:

```yaml
environment:
  - HA_URL=http://homeassistant:8123
  - HA_TOKEN=YOUR_LONG_LIVED_ACCESS_TOKEN
```

`HA_URL` must be reachable from inside the JK-BMS container.

The dashboard synchronizer automatically derives:

```text
ws://homeassistant:8123/api/websocket
```

from the example `HA_URL`.

For HTTPS installations it derives `wss://.../api/websocket`.

An explicit URL can optionally be supplied with:

```yaml
- HA_WS_URL=ws://homeassistant:8123/api/websocket
```

Compatibility aliases from the original standalone prototype are also accepted:

```text
SUPERVISOR_TOKEN
WS_URL
```

Do not store a real Home Assistant token in the Git repository.

## Standalone dashboard URL

The standalone Node-RED Dashboard 2 interface is served inside the container on port `1880` at:

```text
/dashboard/
```

With the example Docker port mapping:

```yaml
ports:
  - "1880:1880"
```

the external URL is normally:

```text
http://<DOCKER-HOST>:1880/dashboard/
```

Do not rely on the IP address detected from inside the container. With Docker bridge networking, that address may be an internal `172.x.x.x` container address and may not be reachable from other devices on the LAN.

To make the JK-BMS log display the exact external URL, optionally set:

```yaml
environment:
  - JKBMS_PUBLIC_URL=http://192.168.1.50:1880
```

Use the actual LAN address or hostname of the Docker host and the externally mapped port.

For example, when using a different host port:

```yaml
environment:
  - JKBMS_PUBLIC_URL=http://192.168.1.50:8180

ports:
  - "8180:1880"
```

the logged dashboard URL becomes:

```text
http://192.168.1.50:8180/dashboard/
```

`JKBMS_DASHBOARD_URL` is accepted as a compatibility alias for `JKBMS_PUBLIC_URL`.

This URL applies only to the **standalone Docker** runtime. It is not the Home Assistant OS add-on URL.

## Automatic Premium HTML dashboard sharing

SmartPhoton Premium HTML dashboards are generated by the JK-BMS container under:

```text
/config/www/
```

To avoid manually copying these files into Home Assistant, mount the Home Assistant host `www` directory directly at `/config/www` inside the JK-BMS container.

Example, when the Home Assistant configuration directory on the Docker host is:

```text
/opt/homeassistant/config
```

use:

```yaml
volumes:
  - jkbms_data:/data
  - jkbms_config:/config
  - /opt/homeassistant/config/www:/config/www
  - /dev:/dev
```

The first two volumes keep JK-BMS runtime data and generated dashboard JSON persistent.

The bind mount:

```text
/opt/homeassistant/config/www:/config/www
```

makes files generated by JK-BMS immediately available to Home Assistant under its normal `/local/...` web path.

Only Home Assistant's `www` directory is shared with JK-BMS; the complete Home Assistant configuration directory does not need to be mounted into the JK-BMS container.

If Home Assistant and JK-BMS run on different Docker hosts, replace the local bind mount with an appropriate shared filesystem mount (for example NFS/SMB) that exposes the Home Assistant `www` directory at `/config/www`.

## Example docker-compose configuration

> Environment variable names for JK-BMS options are derived from the add-on schema declared in `config.yaml`.

```yaml
volumes:
  jkbms_data:
  jkbms_config:

services:
  jkbms-rs485:
    image: {registry}/{owner}/jkbms-rs485-standalone:latest
    container_name: jkbms-rs485

    environment:
      # JK-BMS connection
      - JKBMS_PATH=/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0
      - JKBMS_COUNT=1
      - USE_GATEWAY=false
      - GATEWAY_IP_PORT=
      - COMMUNICATION_DEBUG=false
      - BMS_BROADCASTING=false
      - CAN_BUS_USAGE=false

      # MQTT
      - MQTTADRESSE_PORT=mosquitto:1883
      - MQTTUSER=mosquitto
      - MQTTPASS=super_secret_password

      # Home Assistant direct API access for Lovelace dashboard synchronization
      - HA_URL=http://homeassistant:8123
      - HA_TOKEN=YOUR_LONG_LIVED_ACCESS_TOKEN

      # Optional: exact URL shown in JK-BMS standalone logs.
      # Replace with the LAN IP/hostname of the Docker host.
      - JKBMS_PUBLIC_URL=http://192.168.1.50:1880

    volumes:
      # Persistent JK-BMS state/options/premium install identity
      - jkbms_data:/data

      # Generated Lovelace dashboard JSON and other /config content
      - jkbms_config:/config

      # IMPORTANT:
      # Replace this host path with the actual Home Assistant config/www path.
      # This removes the need to manually copy Premium HTML dashboards.
      - /opt/homeassistant/config/www:/config/www

      # Live host device tree for USB serial re-enumeration support
      - /dev:/dev

    device_cgroup_rules:
      - "c 188:* rw"

    group_add:
      - dialout

    ports:
      - "1880:1880"
```

### `JKBMS_COUNT`

`JKBMS_COUNT` is the **total number of BMS on the bus**.

Examples:

```text
Active polling:
1 = BMS 1
2 = BMS 1 + BMS 2

Broadcasting:
1 = Master only
2 = Master + 1 slave
3 = Master + 2 slaves
```

Do not use `0`.

### Alternative device binding

Direct binding can be used instead of exposing `/dev`, but it generally requires a container restart after USB re-enumeration:

```yaml
services:
  jkbms-rs485:
    ...
    devices:
      - "/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0:/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0"
```
